# State machine inventory

This is a source-level map of the app's user-visible workflows and asynchronous resource lifecycles. It describes transient runtime state; the project model in `site/core.js` and IndexedDB records in `site/storage.js` remain the durable source of user content. A state name below is explicit only when the code represents and checks it as such. Several workflows currently derive state from nullable handles, booleans, DOM properties, and timers.

## Workflow map

| --- | --- | --- | --- |
| Studio navigation and Voice Lab focus | `site/app.js`: URL hash, `body.dataset.screen`, hidden regions, `activeVoiceTool` | hash change → screen; voice tool selection → focused card; leaving Voice Lab stops tuner | Browser smoke covers studio screens and mobile accessibility. ## Audit decision

The highest-value bounded fix found in this pass was the Photos polling deadline. The app parsed the API's `timeoutIn` but only stopped when it was non-positive, then otherwise waited up to a fixed five minutes. `waitForPhotosSelection` now caps polling at the server-provided total timeout (and the existing five-minute safety limit), uses the recommended poll interval, and has deterministic tests for timeout and successful selection. Google documents `timeoutIn` as the total polling window and `pollInterval` as the recommended delay in its [session reference](https://developers.google.com/photos/picker/reference/rest/v1/sessions) and [session guide](https://developers.google.com/photos/picker/guides/sessions).

## Follow-up design guidance

- Keep `CaptureSession` as the pattern for workflows where stale async completions can overwrite a newer user choice: explicit phases, transition guards, and a generation token.
- Add explicit transition helpers only when changing a workflow. The next useful candidates are speech Worker lifecycle and audio-only/AV recording, where transient state currently lives across handles and DOM updates. Avoid a broad rewrite of `app.js` or the project data model.
- For each newly explicit workflow, keep the state owner in one module, make cancel/error cleanup idempotent, and test transitions plus late async completion. Browser smoke should validate the rendered experience; unit tests should own state transition rules.
- Live Google OAuth, real model inference, physical devices, and listening remain separate acceptance checks; current automated evidence does not establish them.
